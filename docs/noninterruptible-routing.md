# Version 0.19: detection and playback have separate responsibilities

The 0.18 run showed repeated Hindi/Tamil/English classification changes. Each source-language change incremented the playback epoch, invalidated in-flight synthesis and made Android flush its AudioTrack. All those languages still needed Telugu output, so those cancellations were unnecessary.

0.19 changes epochs only when the output route changes between translated speech and original audio, or when changing input domains between media and Bubble. Non-target language changes retain the selected output voice, queue and in-flight generation. After initial detection, an output-route change requires two distinct stable source-caption segments across at least 600 ms; repeated callbacks for one segment do not count as two votes. Initial routing uses the first stable caption.

Already accepted synthesis jobs finish despite later detection results. The audio queue reports each completed chunk's final packet sequence. Android records a pending route change but continues the current chunk until its final packet has actually played according to the AudioTrack playback head. It then changes volume/routing and discards queued speech belonging to the superseded route. It does not wait for the entire queue during continuous playback. A chunk boundary is an audio-generation boundary, which may be shorter than a grammatical sentence when provider text is split by the UTF-8 request limit.

The unified backend retains one Session, channel, control connection, STT agent, Conversational AI voice agent and direct Murf generation connections. Android retains its engine and two publisher identities joined once: media UID 1001 is subscribed by Agora STT; microphone UID 1002 goes to the Qwen command detector. The two inputs use separate custom audio tracks and never mix. Bubble replies still use Agora Conversational AI Engine with Murf Falcon; media keeps parallel direct Falcon generation.

Pausing media or tapping Ask Bubble requests an input change instead of closing/rejoining. Source media is gated to silence while the backend finishes known generation and playback acknowledgments, plus a two-second quiet interval for late captions. A short-lived empty queue is not sufficient. Microphone capture starts only after the mode becomes Bubble and the phone is unlocked; locking releases the microphone while retaining the RTC session. Returning to media waits for a current Bubble answer to finish and starts from fresh media frames. No historical capture buffer is replayed. Session expiry, disconnect, Disable or a terminal provider error still closes resources.

Memory remains installation-scoped. Caption latency and uncertain recognition upstream can still cause gaps; retained transport and uninterrupted playback do not remove those provider delays. Late captions received after the microphone handoff are not treated as microphone commands. Timestamped captions predating a fresh media segment are excluded from new translation generation.

The native phone test exercised actual AudioTrack playback acknowledgments and two isolated Agora publisher tracks, translated a synthetic cooking recording, recalled its captions with Qwen, spoke the answer through the Agora/Murf agent, then returned to media with the same session ID. Metadata-only `AnyVoicePlayback` logs record route handoffs, completed chunk, played sequence and required boundary sequence.

Rollback: source tag `anyvoice-before-noninterruptible-routing`; APK `dist/AnyVoice-rollback-before-noninterruptible.apk`; Docker image `anyvoice-backend:rollback-before-noninterruptible`. Existing SQLite memory remains compatible.
